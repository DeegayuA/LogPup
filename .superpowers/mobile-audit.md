# LogPup mobile usability audit

Scope: every route under `src/app/(app)/`, `src/app/(public)/`, `src/app/print/`, and the
top-level auth/status pages, plus the dialogs/sheets/panels called out as high-risk (meeting
form, meeting detail dialog, task dialog, sprint edit dialog, ⌘K command centre, meeting
intelligence panel, datetime picker). Audit-only — no fixes applied, nothing committed.
Method: read source + Tailwind classes directly; no dev server was used. Every finding below
cites `file:line`. Severity: **Critical** = unusable or overflows on a 375px viewport, **Major**
= painful but usable, **Minor** = polish.

Target device baseline for "does it fit": 375×667 (iPhone SE / small Android), since that's the
narrowest realistic device this internal tool needs to survive on.

## Top 10 by impact (fix these first)

1. **Kanban card drag is likely non-functional on touch** — `task-card.tsx` is missing the `touch-action: none` fix the codebase already applies to the meetings time-grid's drag blocks. This is the single highest-risk item: it's the core "move a task" gesture on the app's busiest work surface, and the fix is a one-line, already-proven pattern elsewhere in this same repo.
2. **Print route can overflow the page horizontally** — no `overflow-x-auto` wrapper around the meeting-record table(s), plus fixed `18mm` screen padding eating over a third of a 375px viewport.
3. **Meeting form's Starts/Ends fields squeeze into unreadable buttons** — `grid-cols-2` with no `sm:` collapse, the one inconsistent dialog in an otherwise-consistent pattern.
4. **"Type CLEAR to confirm" silently fails on phone keyboards** — missing `autoCapitalize`, case-sensitive server check.
5. **Kanban quick-add has no tappable submit** — Enter-only task creation on the busiest mobile surface in the app.
6. **Chip remove-buttons (attendees, tech tags, org tags) have their 44px touch-target expansion clipped** — a documented gap in the shared `Badge` recurring in 3 places.
7. **New sprint dialog's date fields squeeze the same way** as #3, one severity notch down.
8. Verify the kanban's drag-grip keyboard handle (`task-card.tsx:247-262`) once #1 is fixed — same missing `touch-action`.
9. Normalize the App header's 6-stat grid to start at 2 columns like every sibling stat row, for consistency and a little more breathing room.
10. Bulk-action bar and board toolbar density on mobile — not broken, but the busiest-looking screen in the app; worth a "More" menu pass once the above are fixed.

## Systemic patterns (fix once, not N times)

- **Horizontal-scroll-in-a-container is the house pattern for wide content, and it's applied consistently and well.** The kanban board (`board.tsx:486`), the roadmap timeline (`roadmap-timeline.tsx:626`), the roadmap spine (`roadmap-spine.tsx:195`), the month calendar (`meetings-month-calendar.tsx:359`), the app section tab bar (`app-tab-nav.tsx:28`), the status-filter segmented control (`apps-browser.tsx:108`), and every data table via the shared `Table` primitive (`components/ui/table.tsx:9-11`, which wraps every `<table>` in `overflow-x-auto` automatically) all do this correctly. The print route (finding above) is the one place this pattern was skipped — worth grepping for any other bare `<table>` that bypasses the shared `Table` component the same way.
- **`touch-action: none` on dnd-kit draggables is understood and applied inconsistently.** It's correctly set (with a good explanatory comment) on the meetings time-grid's draggable blocks (`meetings-time-grid.tsx:922-924`) but missing on the sprint board's task cards (`task-card.tsx`). One shared helper/class (e.g. a `dnd-touch-none` Tailwind utility documented next to the coarse-pointer rule in `globals.css`) applied to both `useDraggable`/`useSortable` call sites would close this for good and prevent the next drag surface from repeating the gap.
- **Touch-target sizing is solved once, well, at the CSS layer** — the `@media (pointer: coarse)` rule in `globals.css:292-340` expands every `<button>`, `[role="button"]`, and `[data-slot="select-trigger"]` to a 44×44 hit area via an invisible `::after`, without changing any visible box size. This is a genuinely good, low-maintenance solution and it's why most icon-only buttons in this audit did **not** need individual touch-target findings. Its one documented blind spot — controls inside an `overflow: hidden` ancestor — is exactly what's biting the `Badge` remove-buttons above; fixing that one shared component (or documenting the pattern for anyone who reaches for `Badge` + a nested button again) is higher leverage than three separate patches.
- **Two-up form grids (`grid-cols-2` for a pair of related fields) are collapsed to one column below `sm:` almost everywhere, except two dialogs that forgot the prefix** (meeting form's Starts/Ends, new-sprint's Start/End date). Both are one-line fixes; worth a quick repo-wide grep for `grid-cols-2` (or `grid-cols-3`+) with no responsive prefix before closing this out, in case a similar dialog was added since this audit.
- **16px input font size (the iOS-zoom rule) is already solved at the primitive level**, not per-instance: `Input` and `Textarea` both default to `text-base` (16px) and only shrink to `text-sm` at `md:` (`components/ui/input.tsx:12`, `components/ui/textarea.tsx`). No individual input in the app needed a finding for this — it's correctly systemic already.

## Already good (do not churn these in the fix pass)

- **Navigation.** `MobileNav` (`components/shell/mobile-nav.tsx`) renders the exact same `navItems`/`adminNavItems`/`NavLink` as the desktop `Sidebar` — no missing destinations. It's built on the real `Dialog` primitive (focus trap, `aria-modal`, Escape, focus return all come free) rather than a hand-rolled sheet, and correctly closes on route change. `Header` (`components/shell/header.tsx`) swaps the sidebar's footer controls (account, install button) into the header row exactly once at each width via `md:hidden` pairs — no duplicated or missing controls at either breakpoint.
- **The datetime picker popover fits 375px.** `w-[min(22rem,calc(100vw-2rem))]` (`components/ui/datetime-wheel.tsx:335`) resolves to ~343px on a 375px screen; its calendar + two 104px-wide hour/minute wheel columns fit comfortably inside that with room to spare. Every wheel row is a documented 44px tap target (`ROW_HEIGHT = 44`, `datetime-wheel.tsx:28`).
- **The command centre (⌘K)** (`features/search/components/command-center.tsx`) uses the same `Dialog` primitive with a bounded `max-h-[calc(100svh-2rem)]` and its own nested `max-h-72` scrolling result list — no overflow risk at any height. `CommandDialog`'s width (`sm:max-w-xl`, `components/ui/command.tsx:56-60`) falls back correctly to the base dialog's `max-w-[calc(100%-2rem)]` on mobile.
- **The meeting intelligence panel** (`meeting-panels.tsx`) is genuinely well adapted: `PanelsLayout` stacks the nav rail above the content on mobile and only goes side-by-side at `lg:` (`meeting-panels.tsx:364-374`), and `PanelNav` itself becomes a horizontally-scrolling chip row below `lg:` instead of wrapping or clipping (`meeting-panels.tsx:335-336`). Every filter chip row (`FilterBar`) wraps freely.
- **Meetings' calendar entry point already special-cases narrow screens**: `meetings-views.tsx:189-192` explicitly defaults to **Day** (not Week) when `isWide === false`, with a comment explaining Week is "unusable on a phone" — and the top-level switcher defaults to **List** over Calendar. This is exactly the kind of default-to-the-simpler-view judgment call the audit brief asked the kanban question about; meetings already made it.
- **Bilingual/Sinhala text has a dedicated, already-shipped utility**: `bilingualText = 'text-sm/6 break-words'` (`meeting-chips.tsx:47`) gives bilingual content generous line-height and wraps rather than clips. No fixed-height `overflow-hidden` container holding translatable text was found anywhere in the audited surfaces — stat tiles use `min-h-`, not `h-`/`max-h-`, specifically so taller (e.g. Sinhala) content can grow the box instead of being cut off (`person-stat-row.tsx:52`, explained in that file's own comment).
- **Every dialog in the app funnels through one `DialogContent` base class** (`components/ui/dialog.tsx:63`) that already handles the hard mobile dialog problem correctly: `max-h-[calc(100svh-2rem)]` + `overflow-y-auto` (with a code comment explaining exactly why `svh` and not `vh`/`dvh`), full-width minus a 2rem margin below `sm:`, and a sticky-looking footer (`DialogFooter`, `:100-125`) that stacks buttons `flex-col-reverse` on mobile so the primary action is always the first one reachable by thumb. Task dialog, sprint-edit dialog, assign dialog, and meeting-detail dialog all inherit this for free and were not re-litigated individually above.
- **Sign-in, pending-approval, and auth-error pages** are already single-column-first (`lg:grid-cols-2` on sign-in collapses correctly; `pending`/`auth-error` never had a second column) with `max-w-sm`/`max-w-md` cards and generous `p-4 py-10` padding — nothing to fix.
- **Forms are already using the right input affordances**: phone fields, numeric fields (allocation %, capacity heat, check-in %) and the meeting link field all set `inputMode` and `autoComplete` correctly (`auth/components/phone-field.tsx:57-58`, `people/components/assign-dialog.tsx:158`, `meetings/components/meeting-form.tsx:619`, etc.) — `db-clear-button.tsx`'s missing `autoCapitalize` (flagged above) is the one gap found in an otherwise-consistent set.
- **App tab bar and the apps-list status filter** both deliberately scroll horizontally instead of wrapping, with a code comment on the tab bar explaining exactly why ("seven sections wrap to two rows at 375px... a single scrolling row keeps the 'these are peers' reading intact") — this is the right call and already shipped.

## Summary

- **Critical: 2** — kanban touch-drag likely broken; print route can overflow horizontally.
- **Major: 6** — meeting form date-grid squeeze; sprint-form date-grid squeeze; DB-clear `autoCapitalize` gap; chip remove-button touch-target clipping (3 instances, 1 systemic fix); kanban quick-add has no tappable submit; (grouped toolbar/bulk-bar density folds into Minor below).
- **Minor: 4** — board toolbar/bulk-bar visual density; app-header stat-grid inconsistency; month-view calendar cell compression (already largely mitigated); pervasive 11px meta text.

**Worst page: the sprint board (kanban).** It's the one place a Critical (likely-broken touch drag) and a Major (no visible "add task" button) land on the same screen, and it's also the app's busiest work surface — the exact "hardest thing on this list" the brief called out.

**Top 3 systemic patterns:**
1. Wide content already scrolls inside its own container almost everywhere (tables, kanban, roadmap, month calendar, tab bars) — a strong, consistent house pattern; the print route's bare `<table>` is the one place it was skipped.
2. `touch-action: none` on drag surfaces is understood (meetings time-grid) but not applied everywhere it's needed (sprint board task cards) — one shared utility/convention would close this permanently.
3. Touch-target sizing is solved once at the CSS layer (`@media (pointer: coarse)` 44px hit-area expansion), with exactly one documented blind spot — controls inside an `overflow-hidden` ancestor — which is what's clipping the `Badge` remove-buttons in three places.
