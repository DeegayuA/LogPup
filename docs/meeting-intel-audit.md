# Self-teaching audit — meeting notes & intel

**Date:** 2026-08-19 · **Scope:** the meeting notes/intel surface deferred by `docs/self-teaching-audit.md` — `meeting-intel.tsx` (4,074 lines), `meeting-notes.tsx`, `note-timeline.tsx`, `action-item-board.tsx`, `meeting-notes-dialog.tsx`, `meeting-panels.tsx`, `src/features/transcription/**`, `src/features/speech/**`, `src/features/gemini/**`, and the follow-up read path into `/people/[id]` and the dashboard. Read-only.
**Same three questions:** what is this screen for · what is the one action I should take right now · what happens after I take it.

**Headline:** the parent audit found a copy-quality surface with structural gaps. This one is the opposite. The prose here is the best in the product — the Clear-notes dialog, the `DueChip`, the failed-segment panel and `AddFollowupForm`'s consequence line are patterns the rest of the app should be measured against. What stops a first-time user is that **the most consequential claims on the surface are not true, and the most consequential actions are silent**. A recording ends without a word if you navigate away; the cost notice promises an auto-stop that guards the socket and not the recorder; the write-up says "Written up by AI" over text a human rewrote; "Analyze again" overwrites the summary while duplicating the record; "Add to meeting notes" writes to a field the panel cannot read; and the AI creates and assigns real tasks to colleagues under a disclosure that says only "make sure attendees consent to recording". Every one of these is a claim the code contradicts, and the parent audit's own standard — *a claim that cannot be verified in the code is worse than no claim* — is the standard they fail.

## 3. What this surface teaches well

These are the patterns worth exporting, not praise. Each is verified at the anchor given.

- **`live-transcription-status.tsx:26-28` — never let "the machinery started" masquerade as "it is working."** The `listening` state reads "Connected — nothing transcribed yet. Speak to check it is hearing you." A connected socket and a working one are named as different things, and the copy hands the user a one-second test they can run themselves. This is the single best sentence in the surface and exactly the discipline fix #3 is missing. Apply it to every connect/sync/upload status in the app.
- **`live-transcription-status.tsx:73-85` — condition-scoped notice, not event-scoped toast.** Degradation renders as a persistent `role="status"` paragraph, with the comment recording why: "a silently-degraded transcript is exactly the failure mode this feature exists to avoid." The app elsewhere leans on 4-second toasts for facts that outlive them — `runFinalize`'s `'live-transcript'` notice at `meeting-intel.tsx:1850` is the counter-example in this very file.
- **`meeting-intel.tsx:3025-3099` — the best error state in the product.** Names the failure per segment, prints the byte size, says where the audio physically is and that it survives a reload, marks recovered ones as recovered, offers a per-item Retry, and is deliberately `--warning` not `--destructive` because nothing is lost. Audit every destructive-looking error state in the app against it. `:3070` earns its own mention: it refuses to print "failed after N tries" because a permanent failure stops after one attempt, so the count would be false in that branch.
- **`meeting-intel.tsx:2637-2665` — the template for every destructive confirm.** Three paragraphs: what is destroyed and cannot be undone, what is only soft-deleted and an admin can restore, and what survives so the work need not be redone ("the recording transcript is kept, so the notes can be written up again without recording the meeting a second time"). Three consequences, three sentences, no hedging.
- **`meeting-intel.tsx:4064` — the best "what happens after I take it" in the product.** `AddFollowupForm`'s live consequence line names the exact meeting and date the item will surface at, says it will *not* appear here, and states the resting state — all derived from current form values, so it cannot go stale. Copy this shape to every form whose output lands somewhere other than the screen you are on.
- **`meeting-intel.tsx:3767` — destructive copy defined against its non-destructive sibling.** "It stops carrying forward because it stops existing — unlike Resolve, nothing in the meeting record says it was addressed. The removal itself is logged." Far more teachable than "this cannot be undone", and the exact template the suggestion ✕ is missing.
- **`action-item-board.tsx:194-213`, `:288-317` — the reference implementation for rendering model output.** A stored date, a model hint that resolved to a date (pre-filled, one click to confirm), and a hint that did not resolve (quoted "Unresolved: …", never styled as a deadline) are three visually distinct things with their own aria-labels. Reinforced by `DueChip` at `meeting-notes.tsx:610` and `meeting-notes-dialog.tsx:404` — *never let a rendering style assert a certainty the data does not carry.*
- **`meeting-intel.tsx:2310`, `:2358`, `:2399` — toasts that name the resulting state, not the verb.** "Back open — it carries to the next meeting", "Saved — still open and carrying forward", "Follow-up added — it comes up at that meeting, not this one." Contrast "Task created" at `action-item-board.tsx:511`. Every toast in the app should be able to finish the sentence "…and now what?"
- **`meeting-intel.tsx:2804-2845` — pre-flight readiness before the commitment, not after every failure.** Also models honest quantification: the capacity estimate is hedged "In the region of… shared with every other AI feature" because Google publishes no per-key balance. `readiness.ts:91-98` and `:126-135` extend it — the headline lists three possible causes instead of diagnosing one, because `failCount` cannot distinguish a rejected key from an exhausted one, and a 12-hour staleness window stops yesterday's failures from telling someone to buy a key they don't need. The verdict words elsewhere in the app ("at risk", "check-in gap") could use this discipline.
- **`meeting-intel.tsx:1904-1913` — honesty implemented in the mechanism, not the copy.** `detachMic` releases the device rather than muting a gain node, specifically so the OS and browser indicators tell the truth: "if the light is on, audio is reaching us." Paired with `:2706-2721`, where the mic toggle is withheld entirely on a mic-only capture because there it would be "a stop button wearing a mute button's label". A control deleted for being unteachable is a pattern the app uses too rarely.
- **`meeting-panels.tsx:577-592` and `meeting-notes.tsx:61-69` — two different nothings, two different UIs.** "The meeting produced nothing for this" and "your filter narrowed this to nothing" are deliberately separate components, and the second always renders a Clear filter control. This is what the parent audit asked `SectionEmpty` to grow, already built here.
- **`note-timeline.tsx:333-360` and `meeting-intel.tsx:3110-3121` — a failed load is not an empty state.** Skeletons shaped like the cards that are coming; a load failure is an inline message plus Retry, with a comment recording the bug it fixed (a load failure used to render as "No AI notes yet", a different and untrue statement).
- **`followups.ts:60-77` — never guess an owner; give the guess-failure its own visible queue.** Attribution routes through confirmed speaker mappings rather than name matching, with the comment naming the harm avoided ("an unconfirmed match here silently made a real person owe work they never agreed to"), and the unresolvable remainder surfaces as Needs attribution with a one-row picker.
- **`speech/dictate-button.tsx:16-20`, `:46`, `:88-91` — the strongest small component in the area.** Three explicitly named states because "a dictation that produced nothing and a dictation still in flight look identical otherwise"; renders nothing at all where `MediaRecorder` is absent rather than showing a button that would fail; carries an sr-only polite live region so colour is not the only signal.
- **`meeting-notes.tsx:302-317` — a warning placed at the moment of risk, not in a help page.** The inline editor states the bilingual hazard before it can be triggered ("Editing only the English half here would delete the Sinhala one") and switches to markdown help when there is no Sinhala.

## 4. Needs a decision, not code

- **Attendee-facing disclosure that a meeting was recorded.** "Make sure attendees consent to recording" (`meeting-intel.tsx:2843`) states an obligation with no mechanism. Nothing marks a meeting as recorded for its attendees, no notification reaches them, and the recording indicator is visible only to the person who pressed the button — everyone else learns of it when AI notes attributed to them appear. The fix (a "Recording started by {name}" note segment, an RSVP-time disclosure, or a meeting-level flag) is a policy call with a legal edge, not a copy change. This is the only claim on the surface where the parent audit's "describes an action instead of offering it" defect has consequences outside the product.
- **Whether `auto_assign_tasks` should default to `true`.** `schema.ts:335`. Fix #6 makes the current default legible; it does not answer whether the AI should create and notify work for other people before any human has read the write-up. Decide before shipping the disclosure — the copy differs.
- **What "Analyze again" should mean.** Today it is both replace (summary) and append (record). Replacing destroys hand edits; appending makes the record read as if the meeting happened twice. Pick one before writing fix #4 — and note that a true replace conflicts with the soft-delete rule unless the prior AI segments are soft-deleted rather than removed.
- **Provenance for an edited write-up.** Distinguishing "AI wrote this" from "AI wrote this and a human corrected it" needs `summaryEditedAt` / `summaryEditedBy` on `meeting_ai_notes` — a migration. Fix #5 is the truthful interim wording, not the answer.
- **Dismissed suggestions have no surface and no restore path.** `status = 'dismissed'` rows are excluded from `fetchTaskSuggestions` and rendered nowhere in `src/`. Against the project's soft-delete rule (no hard deletes, admin trash + restore) this is a hard delete in everything but storage. Whether dismissal is a soft delete that belongs in admin Trash, or a legitimate terminal state that simply needs to be visible on the meeting, is a rule question that determines both fix #11 and fix #12.
- **Which stale threshold is right — 14 or 21.** Fix #18 says delete one; it does not say which. The meeting surface's 21 days and the person/dashboard 14 encode different judgements about when an open follow-up becomes a problem, and the number drives a destructive-red tile.
- **Whether to mount `SpeakerAssignmentPanel`.** Fix #10 restores the best-taught block in the feature, but the component is not inert: its allocation dialog (`speaker-assignment.tsx:272-345`) writes an app assignment that counts towards a person's capacity. Restoring dead code with side effects needs a deliberate decision about that write path, not just a JSX swap.
- **Untranscribed audio is single-device and expires.** `segment-store.ts` parks it in one browser profile's IndexedDB for 7 days, and its own header calls loss here "the one failure in this whole feature that is genuinely unrecoverable." Fix #22 makes the limit honest; making it *not a limit* means server-side parking — storage, cost and retention decisions well outside a copy pass.

## Verification notes

Every finding above was checked against the code; **none were dropped**. Three claims from the area passes were **corrected** before being carried into this report, because they would have sent someone to the wrong place:

1. *"The language select vanishes in Safari and Firefox."* Only Firefox — `liveSupported` (`meeting-intel.tsx:732`) tests `window.SpeechRecognition ?? window.webkitSpeechRecognition`, and Safari ships the latter. The finding stands on its substance (the control is inert on the default Gemini Live path); the browser list did not.
2. *"The trigger reads as 'what language is this meeting in'."* True visually; the trigger already carries `aria-label="Live transcript language"` (`meeting-intel.tsx:2670`), so the defect is a missing visible label, not a missing name. Fix #19 is worded accordingly.
3. *"Nothing in the list view renders `meetings.notes` at all."* Correct for the list view, but `meeting-detail-dialog.tsx:453` does render it — reachable only from the calendar views (`meetings-calendar.tsx:446`, `meetings-month-calendar.tsx:471`). The copied answer is therefore not lost, it is misfiled: fix #8's defect is that the user is told it landed somewhere it did not.

One claim was left out for being unverifiable rather than wrong: the assertion that `speaker-assignment.tsx` "was mounted in 4ca0bb3 and later unmounted". Its zero call sites in `src/` are verified by grep and are the load-bearing part; the commit history is not.
